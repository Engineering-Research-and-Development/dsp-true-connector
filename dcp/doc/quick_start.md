# 🚀 Quick Start: DCP Credential Delivery

## The Missing Endpoint - NOW IMPLEMENTED! ✅

### **POST `/api/issuer/requests/{requestId}/approve`**

This endpoint triggers Step 3 of the DCP flow: delivering credentials to the holder.

---

## ⚡ Quick Test in Postman

### 1️⃣ Request Credentials (as Holder)
```
POST http://localhost:8080/issuer/credentials
Authorization: Bearer <holder-token>
Content-Type: application/json

{
  "@context": ["https://w3id.org/dspace-dcp/v1.0/dcp.jsonld"],
  "type": "CredentialRequestMessage",
  "holderPid": "8a1f5c3e-2b7d-4e9a-9c1d-5f0e7b6a2d41",
  "credentials": [{"id": "membership-credential"}]
}

→ Response: 201 Created
→ Location: /issuer/requests/req-{uuid}
→ Copy the request ID from Location header
```

---

### 2️⃣ Approve & Deliver (as Issuer) ⭐ **NEW!**

**Simple Approval (Recommended for UI):**
```
POST http://localhost:8080/api/issuer/requests/req-{uuid}/approve
Content-Type: application/json

{}

→ Response: 200 OK
Credentials issued and delivered successfully
```

**What happens:**
1. System retrieves the credential request from database
2. **Automatically generates credentials** based on the requested credential IDs
3. Resolves holder's DID to find their `/dcp/credentials` endpoint
4. Sends credentials automatically
5. Updates status to ISSUED

---

**Manual Approval (Advanced - with custom credentials):**
```
POST http://localhost:8080/api/issuer/requests/req-{uuid}/approve
Content-Type: application/json

{
  "credentials": [
    {
      "credentialType": "MembershipCredential",
      "payload": "eyJraWQiOiJkaWQ6ZXhhbXBsZTppc3N1ZXI0NTYja2V5LTEiLCJhbGciOiJFUzI1NiJ9...",
      "format": "jwt"
    }
  ]
}

→ Response: 200 OK
Credentials issued and delivered successfully
```

**Use this when:**
- You have pre-signed credentials ready
- You want to issue custom credentials not auto-generated by the system

## 🎯 Key Points

✅ **Simple Approval:** Just call `/approve` with empty body - credentials are auto-generated  
✅ **Database-Driven:** Request details stored in database, credentials generated from request  
✅ **Automatic Delivery:** Credentials are pushed to holder automatically  
✅ **DID Resolution:** Service resolves holder's DID to find their endpoint  
✅ **Flexible:** Can provide custom credentials in the body if needed  
✅ **Auth Handled:** Authentication tokens generated automatically  
✅ **Status Tracking:** Request status updated automatically  
✅ **Two Formats:** Supports JWT and JSON-LD credentials

## 🐛 Troubleshooting

**Problem:** "Could not resolve Credential Service endpoint"  
**Solution:** Ensure holder DID follows format: `did:web:localhost%3A8080:holder`

**Problem:** "Failed to deliver credentials"  
**Solution:** Check holder's `/dcp/credentials` endpoint is running

**Problem:** "Credential request not found"  
**Solution:** Verify the request ID from Step 1
